# Значения по умолчанию

[← Подсистемы](../README.md) · [Библиотека](../../README.md) · [Все карточки объектов](docs/README.md)

Каталог хранит правила начального заполнения реквизитов и новых строк табличных частей. Правила применяются к переданному объекту в памяти; сам бизнес-объект не записывается. Частично успешные изменения сохраняются в нём, ошибки показываются пользователю. Данные каталога и объекты-потребители в комплект не включены.

## Состав и зависимости

[Манифест файлов и UUID](manifest.json). 25 файлов исходников: подсистема, каталог с тремя управляемыми формами и командой, два общих модуля, две роли и картинка 16×16. Используемая картинка переименована в мямЗначенияПоУмолчанию16; все ссылки согласованы. Неиспользуемая картинка 24×24 не переносится. Подсистема самостоятельная, прежний родитель другого проекта не требуется.

Установите библиотечные модули мямОбщегоНазначения, мямОбщегоНазначенияВызовСервера, мямОбщегоНазначенияКлиентСервер и мямСтрокаКлиентСервер вместе с их зависимостями из корневого manifest.json. Методы выборки объектов требуют справочники идентификаторов метаданных/расширений БСП и их штатное заполнение. Для редактирования комментария формы нужен экспорт ОбщегоНазначенияКлиент.ПоказатьФормуРедактированияКомментария. Проверена зависимость от исходников БСП 3.1.12.323; совместимость импортом в 8.3.27/8.5 не проверялась.

## Создание вручную

1. Работайте в своей конфигурации/расширении по её принятому процессу. Сделайте резервную копию и выгрузку. Не загружайте этот каталог src командой загрузки полной конфигурации: здесь намеренно нет Configuration.xml и чужих регистраций ConfigDumpInfo.xml.
2. Создайте картинку, две роли, два общих модуля и каталог с точными именами из карточек. Свойства, типы/квалификаторы, назначения форм, состав и права приведены в таблицах каждой карточки и в связанных XML. Для общих модулей сохраните серверные контексты, ServerCall и Privileged=false.
3. В каталоге создайте четыре реквизита и три управляемые формы. Воспроизведите дерево элементов, реквизиты, DataPath, события и команды по таблицам форм. Скопируйте связанные BSL-модули объекта, менеджера, форм и встроенной команды. Команда объявлена внутри Catalog.xml; отдельный родительский XML для неё не нужен.
4. Создайте подсистему ЗначенияПоУмолчанию и включите каталог и два общих модуля по её карточке. IncludeInCommandInterface=false сохраняется; настройте доступ к каталогу/команде в интерфейсе принимающей конфигурации самостоятельно. Назначьте роль чтения всем пользователям, для которых нужно применять правила; роль добавления/изменения — тем, кто их редактирует. Автоматического назначения ролей нет.
5. Сверьте полученную нативную выгрузку с карточками: имена, типы, внешние модули, формы, события и права. При ручном создании UUID создаёт платформа; не подменяйте их UUID образца. Формат образцов 2.20, они не доказывают успешный импорт. Для переноса XML через существующую нативную выгрузку сначала согласуйте полный граф и объявления в её Configuration.xml; ConfigDumpInfo/configVersion должен формировать Конфигуратор. Не заменяйте конфигурацию этим фрагментом.
6. Выполните штатные проверки вашей конфигурации, контекстов и интерфейса; затем отдельно проверьте пользователей с чтением/изменением, без права чтения и с RLS. В этой поставке платформа не запускалась.

## Подключение заполнения

В источнике используются прямые вызовы из ОбработкаЗаполнения модулей объектов, а не самостоятельная подписка на событие. Подписка и объекты-потребители поэтому не создаются. Добавьте вызов в обработчик нужного объекта, сохранив его существующую логику и порядок:

```bsl
Процедура ОбработкаЗаполнения(ДанныеЗаполнения, ТекстЗаполнения, СтандартнаяОбработка)
    мямЗначенияПоУмолчанию.ПрименитьКОбъекту(ЭтотОбъект);
КонецПроцедуры
```

Не заменяйте уже существующий обработчик целиком. Настройки поддерживают семейства, перечисленные в мямОбщегоНазначенияКлиентСервер.ПоддерживаемоеСемейство. Путь хранится в виде Семейство.ИмяОбъекта.ВидРеквизита.Имя либо Семейство.ИмяОбъекта.ТабличнаяЧасть.ИмяТЧ.ВидРеквизита.Имя. Для новой строки табличной части КоличествоПовторов — целое 1–99. Правила выполняются по Коду и Ссылке; повторный вызов может повторно добавить строки. Автоматического запрета повторного применения нет.

## Права и побочные действия

Порядок применения правил настраивает администратор с полными правами. Это эксплуатационная роль: код не проверяет назначение роли администратора и по-прежнему использует штатные права Чтение и Изменение каталога.

НастройкиОбъекта читает каталог с обычными правами и RLS, без привилегированного режима. Прямое чтение без права Чтение отказывает исключением. ПрименитьКОбъекту проверяет то же право внутри прежнего try: при отказе показывает безопасное сообщение, ничего не заполняет и не запрещает дальнейшее создание бизнес-объекта. Это не проверка права записи бизнес-объекта; его штатная запись выполняется вызывающей конфигурацией.

Перестановка кодов через серверные точки требует Чтение и Изменение до запроса и транзакции; те же проверки есть в вызываемом серверном модуле. Привилегий и новой администраторской роли нет. УменьшитьКод/УвеличитьКод(Код, ВыбраннаяСсылка = Неопределено) проверяют числовой ожидаемый код. Без ссылки действует прежний интерфейс: переставляется единственное правило с данным кодом сейчас. При переданной ссылке требуется её совпадение с целью; форма передаёт ссылку вместе с ожидаемым кодом, поэтому переиспользованный устаревший код не выбирает другую запись. Ссылка должна иметь тип СправочникСсылка.мямЗначенияПоУмолчанию. Входные параметры не меняются. Перед чтением берётся исключительная управляемая блокировка всего каталога, затем читается точная цель с Код = ожидаемому (ПЕРВЫЕ 2) и ближайшие соседи строго ниже/выше (ПЕРВЫЕ 2, код по убыванию/возрастанию). Если второе совпадение имеет тот же код, сосед неоднозначен. Запроса всего каталога и РАЗРЕШЕННЫЕ нет; коды с противоположной стороны не входят в направленный отбор. Отказ чтения цели или выбранных кандидатов соседа откатывает операцию без записей. При отсутствии пары, на границе или дубликате кода цели/соседа записей нет. Пропуски сохраняются: два фактических кода обмениваются. CheckUnique=false в XML не меняется, временный код не используется, выполняются две записи. ПередЗаписью проверяет путь и значение, ПриЗаписи не меняет каталог; обе записи остаются в одной транзакции. При ошибке выполняется штатный откат, затем запись в журнал; ошибка наружу не перевыбрасывается. Прежняя модель вложенных транзакций сохранена: откат внутри вызова затрагивает активную транзакцию платформы, вызывающий код должен учитывать эту границу. МаксимальныйКодЗначенияПоУмолчанию требует Чтение. Обычные права платформы на добавление/изменение каталога сохраняются, обхода RLS нет.

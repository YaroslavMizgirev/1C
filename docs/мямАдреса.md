# мямАдреса

[← Библиотека](../README.md) · [BSL](../modules/мямАдреса.bsl)

Два серверных входа используют локальный адресный классификатор БСП. Универсальность относится к отсутствию частных справочников принимающего проекта; без регистров, данных и сервисов адресного классификатора модуль не автономен. Сетевых запросов и загрузки адресных данных модуль не выполняет.

Экспортные методы перечислены в [карточке зависимостей](мямАдреса-зависимости.md). Используются в том числе служебные модули БСП: перенос на другую версию требует сверки API и формата данных.

## Общий результат двух входов

Поля проверены по конструкторам, последующим присваиваниям и вставкам в исполняемом коде. Возвращается структура из 12 полей; ссылки принимающего проекта и маркер сопоставления отсутствуют. КодФИАС — строковый целевой UUID поиска, не UUID найденного района.

| Поле | Тип | Начальное значение ФИАС / контактная форма | Когда меняется / смысл |
|---|---|---|
| Статус | Строка | NOT_FOUND / PARTIAL | FOUND, PARTIAL, NOT_FOUND, AMBIGUOUS; правила режимов ниже. |
| КодФИАС | Строка | нормализованный входной UUID / пусто | В режиме формы UUID дома при наличии признаков дома, иначе объекта из JSON. После разбора сохраняется и при ненахождении; строкой адреса UUID не угадывается. |
| Представление | Строка | пусто / входное Представление | ФИАС: только успешное штатное форматирование. Форма: сохраняется входное даже при PARTIAL. |
| XML | Строка | пусто / входная КонтактнаяИнформация | ФИАС: штатное построение при FOUND; при ошибке форматирования пусто. Форма: сохраняется входной XML, заново не строится. |
| МуниципальныйАдрес | Строка | пусто / пусто | Полная муниципальная ветвь и полный дом; для формы также согласованность. Наличие исходных строк не проверяется в этой ветке. У формы включает помещения. |
| АдминистративныйАдрес | Строка | пусто / пусто | Полная административная ветвь и полный дом; в режиме формы также согласованность; наличие исходных строк для заполнения этого поля не требуется. |
| МуниципальныйРайон | Строка | пусто / пусто | Имя единственного узла уровня munDistrict на полном муниципальном пути; иначе пусто с диагностикой. |
| КодОКАТО | Строка | пусто / пусто | ФИАС: нормализуется из единственной строки дополнительных сведений. Форма: сначала из JSON, при пустом — из единственной локальной строки. Длины 2/5/8/11, иначе пусто. |

| Диагностика | Массив из Строка | новый пустой массив / то же | Накапливает причины неполноты, несогласованности и неоднозначности. Успешный статус не обещает пустой массив. |

### Состояния и отказ

ФИАС: неверный тип, неверный или пустой UUID вызывает исключение до результата. Нет локального кандидата — NOT_FOUND, несколько кандидатов или неоднозначная выбранная ветвь — AMBIGUOUS; неполный путь/дом либо сбой штатного форматирования — PARTIAL. FOUND означает непустые штатные Представление и XML. В остальных состояниях эти поля остаются пустыми.

Форма: вход — Структура со строками Значение (JSON), КонтактнаяИнформация (XML), Представление; нарушение формы входа вызывает исключение. Части JSON разбираются и сверяются с локальным классификатором, исходные строки сохраняются. Другой тип контакта, свободный ввод, неразобранный JSON или отсутствие целевого UUID оставляют PARTIAL. В обеих ветвях поиска (адресный объект и дом) NOT_FOUND при отсутствии кандидата и AMBIGUOUS при нескольких кандидатах устанавливаются только при непустых исходных XML и Представлении; если хотя бы одна из этих строк пуста, сохраняется PARTIAL. FOUND требует хотя бы одну полную согласованную цепочку, полный дом и обе исходные строки. При двух неоднозначных ветвях и обеих исходных строках — AMBIGUOUS; остальные неуспешные ветви остаются PARTIAL. Код и формат исключений запросов/сервисов не подменяются общим успешным результатом.

Внутри каждого результата новые коллекции; переданная структура формы не изменяется. Внутренние помощники могут дополнять общий массив Диагностика, менять Корректно/Согласованность и поля результата — это не самостоятельный публичный API.

### Разделение прикладного сопоставления

В конфигурации УИД перенесите прежние ПрикладныеЗначенияАдреса, ОкругПоКодуОКАТО и РайонПоКодуОКТМО в модуль принимающего проекта. Вызывайте mapper после универсального метода и добавляйте нужные ссылки там. Проверки единственности, приватные типы и данные остаются в проекте. КодКлассификатораАдреса и ЗаполнитьКодОКАТОАдреса сохранены в универсальном ядре; нормализация ОКАТО выполняется в каждой из шести прежних точек mapper. Потребители этой поставкой не изменяются.

Пять тождественных пар помощников объединены в СведенияОДоме, ГрафАдреса, ВетвиАдреса, ВыбраннаяЦепочка и ПредставлениеЦепочки. Сравнивались токены с заменой только имён методов, алгоритмы не изменялись.

## Методы

### ЗначенияАдресаПоФИАС

Экспортный метод.

```bsl
Функция ЗначенияАдресаПоФИАС(Знач КодФИАС) Экспорт
```

Возвращает адрес по UUID из локально загруженного адресного классификатора.
Каждая ветвь обходится до региона без ограничения глубины и числа ветвей.
Данные читаются пакетами новых UUID; общий предок читается один раз за вызов.
Для дома остаётся потоковое чтение и распаковка блоков ХранилищеЗначения.

Параметры:
 КодФИАС - Строка, УникальныйИдентификатор - UUID адресного объекта или дома/строения.

Возвращаемое значение:
 Структура:
  * КодФИАС - Строка - нормализованный входной UUID; сохраняется и при NOT_FOUND.
  * Статус - Строка - FOUND, PARTIAL, NOT_FOUND или AMBIGUOUS.
  * Представление - Строка - штатный текст выбранного адреса без страны.
  * XML - Строка - штатный XML контактной информации выбранного адреса.
  * МуниципальныйАдрес - Строка - полный однозначный муниципальный путь с домом.
  * АдминистративныйАдрес - Строка - полный однозначный административный путь с домом.
  * МуниципальныйРайон - Строка - имя единственного узла уровня 3 полного муниципального пути.
  * КодОКАТО - Строка - нормализованный код уровня 2, 5, 8 или 11 цифр, иначе пустая строка.
  * КодОКТМО - Строка - код муниципальной территории.
  * ОКТМОДома - Число - код найденного блока домов, либо 0.
  * ДополнительныеАдресныеСведения - ТаблицаЗначений - локальные коды кандидата.
  * Диагностика - Массив из Строка - причины неполноты, неоднозначности и предупреждения.

FOUND означает успешное формирование Представления и XML. При остальных статусах эти два поля пусты.
PARTIAL означает, что объект найден, но полный итоговый результат сформировать не удалось.
NOT_FOUND означает, что входной UUID не найден в поддержанных локальных данных.
AMBIGUOUS означает, что найдено несколько вариантов, единственный результат выбрать нельзя.

### ЗначенияАдресаПоКонтактнойИнформации

Экспортный метод.

```bsl
Функция ЗначенияАдресаПоКонтактнойИнформации(Знач ВыбранноеЗначение) Экспорт
```

Дополняет результат штатной формы ввода адреса сведениями локального классификатора.

Параметры:
 ВыбранноеЗначение - Структура - результат формы ввода адреса:
  * Значение - Строка - исходный JSON адреса, содержащий UUID выбранных объектов.
  * КонтактнаяИнформация - Строка - исходный XML контактной информации.
  * Представление - Строка - исходное представление адреса.
  * Тип - ПеречислениеСсылка.ТипыКонтактнойИнформации - необязательный тип, ожидается Адрес.
  * ВведеноВСвободнойФорме - Булево - необязательный признак свободного ввода.

Возвращаемое значение:
 Структура:
  * Статус - Строка - FOUND, PARTIAL, NOT_FOUND или AMBIGUOUS.
  * Представление - Строка - исходное Представление без преобразований.
  * XML - Строка - исходная КонтактнаяИнформация без преобразований.
  * МуниципальныйАдрес - Строка - полный однозначный муниципальный путь с домом и помещениями.
  * АдминистративныйАдрес - Строка - полный однозначный административный путь с домом и помещениями.
  * МуниципальныйРайон - Строка - локальное имя единственного узла муниципального уровня 3.
  * КодОКАТО - Строка - нормализованный код уровня 2, 5, 8 или 11 цифр, иначе пустая строка.
  * КодОКТМО - Строка - код муниципальной территории.
  * ОКТМОДома - Число - локальный ОКТМО найденного дома, для адресного объекта 0.
  * ДополнительныеАдресныеСведения - ТаблицаЗначений - точные строки локального регистра кодов.
  * Диагностика - Массив из Строка - причины неполноты, неоднозначности и предупреждения.
  * КодФИАС - Строка - нормализованный UUID дома либо адресного объекта; иначе пустая строка.

FOUND: UUID подтверждён локальными данными, выбран хотя бы один полный путь,
сведения согласованы, исходные XML и Представление непусты.
PARTIAL: данные формы непригодны или противоречивы, дом повреждён, единственный
путь оборван/зациклен либо отсутствует исходный XML или Представление.
NOT_FOUND: корректные UUID не найдены в точном локальном контексте.
AMBIGUOUS: найдены дубли либо ни в одной иерархии не выбран единственный путь.
При пустом исходном XML/Представлении итог всегда PARTIAL; остальные причины
отсутствия или неоднозначности данных остаются в Диагностике.

### КодКлассификатораАдреса

Внутренний помощник.

```bsl
Функция КодКлассификатораАдреса(ЗначениеКода, Классификатор)
```

Числовые коды локального регистра дополняются ведущими нулями, строковые сохраняются.

### ЗаполнитьКодОКАТОАдреса

Внутренний помощник.

```bsl
Процедура ЗаполнитьКодОКАТОАдреса(Результат)
```

Дополняет КодОКАТО результата из единственной строки дополнительных сведений, иначе добавляет диагностику.

### КандидатыАдресаПоФИАС

Внутренний помощник.

```bsl
Функция КандидатыАдресаПоФИАС(ИдентификаторФИАС)
```

Возвращает совпадения адресного объекта или упакованного дома без выбора первого дубля.

### СведенияОДоме

Внутренний помощник.

```bsl
Функция СведенияОДоме(СтрокаДома, Диагностика)
```

Разбирает части дома; повреждение локальных данных оставляет явную диагностику.

### ГрафАдреса

Внутренний помощник.

```bsl
Функция ГрафАдреса(Кандидат, УровеньРегиона)
```

Читает замыкание родителей пакетами точных UUID. Кеш чтения не является проверкой циклов.

### ВетвиАдреса

Внутренний помощник.

```bsl
Функция ВетвиАдреса(Объекты, Родители, НачальныйUUID, УровеньРегиона, ВидИерархии, Диагностика)
```

Обходит каждый путь в памяти. Пройденные UUID принадлежат только текущей ветви.

### ЗаполнитьШтатныйФорматАдресаПоФИАС

Внутренний помощник.

```bsl
Процедура ЗаполнитьШтатныйФорматАдресаПоФИАС(Результат, Цепочка, Кандидат, Дом, УровниАдреса)
```

Заполняет только штатные Представление/XML, без создания JSON-строки.
Ошибка формата не отменяет доказанные полные текстовые пути.

### ВыбраннаяЦепочка

Внутренний помощник.

```bsl
Функция ВыбраннаяЦепочка(Ветви, Муниципальная, ОКТМОДома, УровниАдреса)
```

Выбирает единственный путь или доказанную муниципальную ветвь по ОКТМО дома.

### ПредставлениеЦепочки

Внутренний помощник.

```bsl
Функция ПредставлениеЦепочки(Узлы, ПредставлениеДома, УровеньРегиона)
```

Формирует текст только выбранного полного пути; все его узлы сохраняются.

### ПроверитьВходПоКонтактномуАдресу

Внутренний помощник.

```bsl
Процедура ПроверитьВходПоКонтактномуАдресу(ВыбранноеЗначение)
```

### ПоляПоКонтактномуАдресу

Внутренний помощник.

```bsl
Функция ПоляПоКонтактномуАдресу(СтрокаJSON, Диагностика)
```

### UUIDПоКонтактномуАдресу

Внутренний помощник.

```bsl
Функция UUIDПоКонтактномуАдресу(ЗначениеUUID, ИмяПоля, Корректно, Диагностика)
```

Разбирает UUID из поля JSON; пустое значение возвращает пустой строкой. При неверном UUID меняет Корректно на Ложь и дополняет Диагностика.

### КодПоКонтактномуАдресу

Внутренний помощник.

```bsl
Функция КодПоКонтактномуАдресу(ЗначениеКода, ИмяПоля, Корректно, Диагностика)
```

Пустой код региона отличается от заданного нуля; коды должны быть целыми десятичными.

### ОбъектыПоКонтактномуАдресу

Читает локальные адресные объекты по UUID и коду региона; возвращает таблицу кандидатов без выбора первого совпадения.

### ДомаПоКонтактномуАдресу

### СогласованДомПоКонтактномуАдресу

Сравнивает части локального дома с JSON формы; возвращает признак согласованности и дополняет Диагностика при расхождении.

### ВетвиМуниципалитетаПоКонтактномуАдресу
